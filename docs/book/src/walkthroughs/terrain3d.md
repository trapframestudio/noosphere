# Terrain3D

[TokisanGames Terrain3D](https://github.com/TokisanGames/Terrain3D) is now
the editor-side terrain plugin for the test path. The Zylann HTerrain
plugin and its GDScript helpers were removed in the same PR. Production
maps still use the Rust `TerrainNode` (`crates/simn-godot/src/terrain.rs`)
for now - that migration is deferred until the Terrain3D path proves
out.

## Why we switched

HTerrain hit two ceilings for our content scale:

1. **16 ground texture layers max** (MULTISPLAT16). We were already at
   the cap with the biome / road set; adding more variants meant
   re-tiering existing layers.
2. **Inline texture-set serialization.** `Texture2DArray._images` is
   `PROPERTY_USAGE_INTERNAL` in Godot core, so `ResourceSaver.save`
   could not externalize the texture set. Any scene that assigned an
   `HTerrainTextureSet` inlined ~700 MB of image bytes - the original
   `hterrain_cascade_locks.tscn` was 683 MB.

Terrain3D supports up to 32 layers, has a region-based on-disk data
format that does not bloat scenes, ships with a `Terrain3DAssets` `.tres`
asset list, and is actively maintained.

## What's installed

- `godot/addons/terrain_3d/` - plugin tree, native binaries for
  Linux/Windows/macOS/iOS/Android/Web. LFS-tracks `*.so` / `*.dll` /
  `*.dylib` / `*.wasm` / `*.framework/**` and the `*.exr` brush
  textures. Plugin v1.0.1, `compatibility_minimum = 4.4`.
- `editor_plugins/enabled` in `godot/project.godot` lists Terrain3D.
- `godot/demo/` (Terrain3D's bundled reference project) is gitignored -
  pull from upstream when you need it as API reference.

## Splatmap → control map (the lossy step)

HTerrain stores up to 16 weighted layers per pixel. Terrain3D stores
`(base_id, overlay_id, blend)` - the top two layers and the blend
ratio between them. `terrain3d_loader.gd` runs three pre-encoding
transforms before packing:

1. **Splatmap softening.** A separable 7×7 box blur on
   `splatmap_a.rgba8` and `splatmap_b.rgba8` so biome-to-biome edges
   read as gradients in the blend channel rather than 1-pixel steps.
2. **Variant distribution.** For supported biomes (Forest /
   Grassland / Bare / Cliff), pick a variant slot from {11..15} by
   argmax across N FastNoiseLite fields, and set blend strength via
   `lerp(min_floor, max_cap, smoothstep(lo, hi, max_v))`. The floor
   is non-zero (50–90 out of 255) so every pixel inside a supported
   biome carries some variant overlay - biome bodies never read as a
   single tile. Where two competing variants' noise values cross,
   the max value is naturally low → strength is low → the slot flip
   happens under a soft overlay where the base shows through. No
   cellular boundaries.
3. **Road encoding.** The 11 raw weights at this pixel are
   `splatmap_a.rgba8` (R/G/B/A → Forest/Grassland/Water/Cropland),
   `splatmap_b.rgba8` (Bare/BuiltUp/Cliff/Snow), `road_density.rgba8`
   (Paved/Unpaved/Trail; alpha unused). Where `max(road_weights)` +
   noise-jittered offset clears a small threshold, the encoder
   writes road as base/overlay against the dominant biome, with
   base = whichever side has the larger share. Both branches use
   the same blend formula so the pixel color is continuous across
   the 50% swap.

Per-pixel encode then packs via `Terrain3DUtil.enc_base |
enc_overlay | enc_blend`, reinterprets as `float32` (`as_float`),
and writes into a `FORMAT_RF` `Image`. Terrain3D's shader does the
inverse with `floatBitsToUint`.

Third+ layers per pixel get dropped. In practice biome boundaries
trigger the `secondary_weight >= 60% * primary_weight` branch (raw
biome→biome blend), variant patches inside biome bodies handle the
rest. Slots 11..15 are *only* populated by the variant pass - the
canonical splat bytes don't carry them.

## Texture slot ordering

Slots are ordered to match the HTerrain MULTISPLAT16 layout the project
settled on across PRs #109–#116, so `base_id` numbers in the control
map align with class order:

| ID | Texture | ID | Texture |
|---|---|---|---|
| 0 | forest_floor (Megascans) | 8 | Asphalt010 (AmbientCG) |
| 1 | wild_grass (Megascans) | 9 | military_trenches_dirt_fine (Megascans) |
| 2 | aerial_ground_rock (water placeholder) | 10 | mossy_rocky_ground (Megascans) |
| 3 | brown_mud_02 (PolyHaven) | 11 | mossy_rock (PolyHaven) - *cliff secondary (lichen)* |
| 4 | Ground073 (AmbientCG) | 12 | rocky_steppe (Megascans) |
| 5 | Concrete026 (AmbientCG) | 13 | mossy_grass (Megascans) |
| 6 | Rock028 (AmbientCG) - *cliff base (dark)* | 14 | nordic_moss (Megascans) |
| 7 | snow_02 (PolyHaven) | 15 | mine_rock_wall (Megascans) - *cliff streak (lighter)* |

> **Cliff routing.** Slots 6 and 15 have swapped texture content
> from the original layout: slot 6 (cliff base) now carries
> `Rock028` - the darkest of the three rocks - and slot 15 carries
> `mine_rock_wall` - the medium-grey quarry stone. Slot 11
> (`mossy_rock`, the lichen rock) sits between them as the wide
> secondary. The variant pass writes `mossy_rock` at floor 80 / cap
> 200 (lichen reads everywhere on the face, peaks as patches) and
> writes `mine_rock_wall` only where its medium-scale noise
> composite crosses 0.72 - narrow streak accents here and there,
> not competing with mossy for area. The dark Rock028 base shows
> through both overlays.

Each slot points at **channel-packed PNGs** in
`godot/assets/textures/terrain/_terrain3d_packed/<slot_name>/`:

- `<slot>_alb_ht.png` - RGBA, RGB = albedo, A = height/displacement
- `<slot>_nrm_rgh.png` - RGBA, RGB = OpenGL-convention normal, A = roughness

Generated by `scripts/pack_terrain3d_textures.py` from the per-bundle
diff/normal/rough/displacement sources still living next to them
(those are kept for the Rust `TerrainNode` shader path, which has its
own samplers and channel layout). For layers without a real height
source (most Megascans + PolyHaven bundles), the height channel is
filled with albedo luminance - same fallback Terrain3D's own
`channel_packer.gd` uses. Re-run the script if a source bundle is
swapped or its mapping in `pack_terrain3d_textures.py` changes.

The `.import` sidecars on the packed PNGs match Terrain3D's
`addons/terrain_3d/menu/channel_packer_import_template.txt`:
`compress/mode=2` (VRAM-compressed), `compress/normal_map=2` on the
normal/roughness pair (preserves the alpha channel rather than BC5
RG-only), `mipmaps/generate=true`, `process/size_limit=2048` so all
32 outputs hit the sampler array at the same edge length.

| `scenes/test/test_map_1.tscn` | `test_map_1` | 4 m | Placeholder canonical (heightmap only, no splatmaps). Bake Now uses the loader's default-biome fallback (see below). |
| `scenes/test/test_map_2.tscn` | `test_map_2` | 4 m | Same shape as test_map_1. |
| `scenes/test/test_map_3.tscn` | `test_map_3` | 4 m | Same shape as test_map_1. |
| `scenes/test/test_map_4.tscn` | `test_map_4` | 4 m | Same shape as test_map_1. |

The test maps keep `TerrainNode` in the tree (sim-side height
sampling + collision still flow through it) but **`visible = false`**
so only Terrain3D renders post-bake. `bake_region_size = 256`
(1024 m per region at 4 m spacing) gives a 5×5 region grid that
fits the 5000 m canonical extent at ~95% fill — the prior default
1024-vertex regions (4096 m) gave a 4-region grid only ~37% filled,
which looked like a small textured island floating in a vast flat
plane.

### Default-biome fallback for splatless canonical

`Terrain3DLoader.bake_into` now tolerates missing
`splatmap_a/b.rgba8` — when both are absent, it fills with
all-zeros and the loader interprets that as "100% biome slot
0" across every pixel. Result: the terrain bakes successfully
to a uniform default-biome surface. Use this for test maps,
prototyping new map IDs, or any canonical that doesn't yet
have a `[features]` block. Authored maps should still ship
real splatmaps from `bake_map` for varied biome rendering.

## Workflow: seed once, sync forever

The Terrain3D regions under `godot/assets/terrain/<map_id>/terrain3d/`
are the **authoritative source for editor edits** once a map has
been seeded. Two operations on the `Terrain3DBaker` node (which
extends `Terrain3D`), each as an inspector tool button:

1. **Bake Now** - one-shot seed from canonical
   `heightmap.r32` / `splatmap_a/b.rgba8` / `terrain.toml`. Defaults to
   `bake_mode = SEED_IF_EMPTY`, which **refuses to overwrite existing
   regions**. Use it on a fresh map. To re-seed an already-baked map
   (and clobber sculpted edits), flip to `OVERWRITE_FORCE` first.
2. **Sync to Canonical** - push live region data back to the canonical
   files. Click after sculpting / painting in Terrain3D so the
   server-side Rust path (`simn_terrain::Heightmap::load`) sees what
   the editor sees, to f32 precision.

Both buttons require a live editor (Terrain3D's native extension
crashes on `add_child()` in headless mode).

### Bake Now (seed)

1. Open `scenes/test/cascade_locks_test.tscn`.
2. Select the `Terrain3D` child.
3. Confirm `bake_map_id = "cascade_locks"`,
   `save_directory_path = "res://assets/terrain/cascade_locks/terrain3d/"`,
   `bake_region_size = 1024`, `bake_vertex_spacing = 2.0`,
   `bake_mode = SEED_IF_EMPTY` (the default).
4. Click **Bake Now**. The script applies `region_size` /
   `vertex_spacing` onto the node, calls `Terrain3DLoader.bake_into(self)`,
   then `data.save_directory(save_directory_path)`. Output is a
   `terrain3d_XX_YY.res` per active region (cascade_locks at
   1024 / 2.0 slices into 6 regions).
5. Save the scene so `data_directory` persists pointing at the freshly-
   written tree.

If region files already exist, the seed bake will fail with an explicit
error pointing at `bake_mode = OVERWRITE_FORCE`. That guard is
intentional — without it, a misclick destroys sculpting / painting work.

### Sync to Canonical (round-trip)

After sculpting (raise / lower / smooth brushes) or painting (texture
brush) in Terrain3D, click **Sync to Canonical** to push the changes
back to the canonical files:

- `heightmap.r32` — literal f32 meters, format_version 2. Sample
  values come from `Terrain3D.data.get_pixel(TYPE_HEIGHT, world_xz)`,
  walked once per canonical grid cell. Bit-exact to the f32 precision
  Terrain3D stores.
- `splatmap_a.rgba8` — Forest / Grassland / Water / Cropland weights.
- `splatmap_b.rgba8` — Bare / BuiltUp / Cliff / Snow weights.
- `road_density.rgba8` — Paved / Unpaved / Trail weights.
- `terrain.toml` — `blake3` digest is recomputed via the gdext
  `TerrainHash` helper. `vert_min_m` / `vert_max_m` auto-expand if
  sculpting overflowed the previous range. Other fields preserved
  byte-for-byte (line-by-line rewrite preserves comments + ordering).

**What does NOT round-trip:**

- **TYPE_COLOR** (the cosmetic distance-LOD biome tint). Color paint
  in Terrain3D survives in the `.res` regions; it's not consumed by
  the server.
- **Variant slots 11–15** (mossy_rock, rocky_steppe, mossy_grass,
  nordic_moss, mine_rock_wall) are noise-driven decoration applied
  during the seed bake. Painting with these slots survives in
  `.res` until the next overwrite-force seed bake; the synced
  canonical splat captures only the underlying biome (slots 0–10).
  Paint with biome slots if the change should survive a re-seed.
- **`features.r8`** — derived from splat + slope at bake time.
  Sync clears `features_blake3` so the next consumer that needs
  `features.r8` re-derives it from the synced splat + heights.

**Out-of-region cells** (where `data.get_pixel()` returns NaN) fall
back to the previous canonical bytes for that pixel, so the unbaked
edges of the canonical map don't regress to zero.

### Rebake Vegetation (whole map)

Third tool button on the same node. Walks the edited scene root for
every TreeScatter / RockScatter / GroundCoverScatter descendant and
calls each scatter's whole-map bake (`_bake_cache_whole_map`). Useful
after a re-seed (`OVERWRITE_FORCE` Bake Now) or for first-time map
setup so gameplay never hits an on-demand bake — every tile loads
from the committed cache.

Cost is real: cascade_locks at default densities is several minutes
per scatter type. Logs per-scatter progress (tiles done / total / ETA),
then a workspace-level "rebake vegetation COMPLETE" line at the end.

The button doesn't auto-chain off Bake Now — that's intentional; the
scatter caches are committed and stable per CLAUDE.md, so re-baking
is a deliberate action (player worlds re-roll). Click manually when
the workflow demands it.

It also intentionally does NOT cover `TreeCoverageBaker` (distant-tree
tint texture, consumed by the Terrain3D shader) or
`TreeClusterScatter` (distant impostor cards), and does NOT
canonicalize. Use **Bake Everything** below when those need to
update too — typically after adding or moving exclusion zones.

### Bake Everything (zones → scatters → canonical)

Fourth tool button. Single-click full chain when you want every
procedural surface refreshed — most often after adding or moving a
`ProceduralExclusionZone`, since exclusions only land where the
relevant baker runs. Strict ordering:

1. `TreeCoverageBaker.bake()` — writes `tree_coverage.res`. Bound to
   the Terrain3D shader's `tree_coverage_map` uniform (distant-tree
   tint) and consumed in step 5.
2. `RockScatter._bake_cache_whole_map()` — rocks first because they
   publish `_tile_tree_exclusions` that step 3 consumes.
3. `TreeScatter._bake_cache_whole_map()` — close-tier trees see
   exclusion zones AND rock exclusions.
4. `GroundCoverScatter._bake_cache_whole_map()` — close-tier plants.
5. `TreeClusterScatter._bake()` — distant impostors, reads the
   coverage texture from step 1.
6. `Terrain3DExporter.export_canonical()` — push live Terrain3D
   height + splat to canonical `.r32` / `.rgba8`.

Stages without matching nodes in the scene log "no nodes (optional,
skipped)" and continue — only the three core scatters
(rocks/trees/ground cover) are universally expected.

Cost: cascade_locks runs ~5–10 min end to end. Reload the scene
afterward to drop in-memory MMIs that were spawned before the
rebake; runtime spawns from the fresh cache files on tile entry.
The strict rock-then-tree ordering also makes this a more correct
choice than `Rebake Vegetation` when scene-tree authoring put trees
above rocks.

### Why `bake_region_size` / `bake_vertex_spacing` aren't direct properties

Setting `region_size` directly in the `.tscn` (e.g. `region_size = 1024`
on the Terrain3D node) **crashes the C++ plugin during scene load**.
The setter runs before `data` is initialized, derefs into uninitialized
memory, segfaults at the same `terrain_3d_init` / `_M_realloc_insert`
offsets every time. Reproduced bisect-narrowed in PR
[migration commits, 2026-04-27]:

```
godot/scenes/test/terrain3d_minimal.tscn       loads ✓
+ assets ref                                   loads ✓
+ baker script attachment                      loads ✓
+ vertex_spacing = 2.0 in .tscn                loads ✓
+ region_size = 1024 in .tscn                  CRASH
```

The baker carries `bake_region_size` / `bake_vertex_spacing` exports
instead. They're applied onto `self.region_size` / `self.vertex_spacing`
inside `_set_bake_now()`, where `data` is fully initialized. The .tscn
keeps Terrain3D at its default `region_size = 256` until the bake
runs, then the bake writes regions at the requested size. After the
first successful bake, `data_directory` points at the on-disk regions
and Terrain3D loads them at their stored size - so the editor never
needs to know the runtime size from the scene file.

After the first seed bake, the **`.res` regions are canonical** for
height + splat - `Sync to Canonical` is the one-way path back to
`heightmap.r32` / splatmaps / `terrain.toml`. Re-running the seed
bake (with `OVERWRITE_FORCE`) is rare and intentional, e.g. after
swapping the upstream DEM or rebuilding the bake spec. Fresh checkouts
pull the `.res` files via LFS.

## Coordinate conventions

Terrain3D treats every texel as a vertex (no `(W-1)*spacing` edge
convention). Regions stitch by sampling neighbors' edge pixels. To
match the rest of our codebase (which uses `(W-1)*spacing` extent
centered on world origin), `terrain3d_loader.gd` imports at world
position `Vector3(-extent_x/2, 0, -extent_z/2)`. Player + ground
cover scatter then see the terrain centered the same way they did
under HTerrain / `TerrainNode`.

## What's still TODO

1. **Production map migration** - the maps under `godot/scenes/maps/`
   continue to use the Rust `TerrainNode`. Once the Terrain3D test path
   proves out, the open question is whether to keep `TerrainNode` for
   the runtime+server path and use Terrain3D only for editor authoring,
   or migrate end-to-end. Punt until we like what we see.
2. **Texture fidelity tuning** - the channel pack landed but the
   default `Terrain3DMaterial` shader params (`mipmap_bias`,
   `noise_scale`, `enable_macro_variation`, `blend_sharpness`) and
   per-asset `uv_scale` / `normal_depth` / `ao_strength` haven't been
   tuned yet. The terrain reads softer-than-HTerrain at gameplay
   distance; iteration belongs in the Inspector on the
   `Terrain3DMaterial` resource embedded in the test scene.
3. **Slots 11..15** - `terrain3d_loader.gd` doesn't write them (the
   canonical splat bake doesn't carry that data). Either hand-paint
   the cliff / forest / grassland variants or let Terrain3D's
   autoshader pick them up via slope/height rules.
